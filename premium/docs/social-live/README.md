# Social Live server contract

Install `2026-10-28-social-live.sql` once after the installed community-friendship and OPS Live V2 schemas. No real database or deployment was changed by this implementation. The friendship control must be enabled. Set `socialLiveEnabled:true` on the deployed `createCoachingHandler` (default false); retain `friendshipsEnabled:true`. API authentication uses the verified bearer identity and enabled pilot profile, never a supplied actor.

Service-role RPCs (all invoker, empty search path; anon/authenticated have no execute/table grants):

- `community_social_snapshot(p_actor uuid) -> jsonb`: existing friendship snapshot plus `socialVersion:1`, `following:uuid[]`, `livePermissions:[{peerId,enabled}]`. Live permissions describe actor-to-peer grants.
- `community_social_command(p_actor uuid,p_peer uuid,p_action text,p_command_id uuid,p_expected bigint,p_enabled boolean default null,p_permission text default null) -> jsonb`: existing actions delegated unchanged; `follow`/`unfollow` persist independently; `set-contact-permission` with `live_access_authorized` requires accepted friendship and matching relation version. Changes owner-to-peer Coaching Live and calls existing OPS habitual grant authority. Explicit enable can restore a revoked OPS habitual grant; default/backfill never does.
- `community_member_search(p_actor uuid,p_query text) -> [{id,displayName}]`: enabled profiles, literal case-insensitive display-name substring or exact UUID; 2–100 characters; maximum 30; no email.
- `community_live_sessions(p_actor uuid,p_session_id uuid default null) -> [{id,owner_id,state,version,updated_at}]`: server-internal raw state. Every invocation checks accepted friendship and owner-directed `live_enabled`, enabled profiles and active phase; owner can also view. Maximum 30 newest. Never expose this raw RPC result to clients. HTTP converts it to a dedicated allowlisted projection.

HTTP operations: `community-live-list` returns `{version:1,sessions:[{id,ownerId,title,mode,phase,version,updatedAt}]}`; `community-live-read {sessionId}` returns `{projection:{id,ownerId,title,mode,phase,version,readOnly:true,role:'observer',pose,search,map}}`. `map` contains `gpsPose`, `gpsSearch`, empty events and hidden endpoints. GPS contains only phase/timestamps and coordinate segments, never actor identity. Normal allows pose+search; Simple Blind search only; Double Blind neither. In Double Blind, ownerId is null to avoid identifying a tracer who owns the session; isOwner is computed from the authenticated viewer for list/read in every mode. No reference, briefing, member list, message, command, invitation, private notes or dossier enters the projection. Observer reads never create membership or alter roles. `community-member-search {query}` returns `{members:[{id,displayName}]}`.

Friend acceptance initializes directional Live access and absent OPS habitual grants. Existing accepted pairs receive these defaults on install. Existing OPS revoked rows stay revoked and initialize the corresponding new Coaching Live permission to false. Existing social permission rows are never overwritten by defaults. Existing explicit Live withdrawals survive removal/reacceptance. Removing an accepted friendship sets both directional Live permissions false while retaining follow state, and immediately prevents observer Coaching reads and revokes both OPS habitual/current grants using `ops_live_habitual`; publication `sharing` is never enabled. Quick Coaching invitation permissions are unchanged. A narrow trigger synchronizes legacy OPS habitual checkbox updates to existing accepted-friend social edges; publication-scoped grants/revocations and stranger grants do not change social permissions.

Validation: `node --test premium/tests/community-social-live.test.mjs premium/tests/community-friendship-http.test.mjs premium/tests/community-friendship-adapters.test.mjs` passes (11 tests). `node --test premium/tests/community-social-sql.test.mjs` passes against local PGlite using the actual core, friendship, and full OPS migration, covering defaults, preserved revocation, permission withdrawal, idempotence, removal, reacceptance and raw access denial. `premium/tests/community-social-live.sql` is an additional rollback-only development database fixture and was not run against a remote database.
